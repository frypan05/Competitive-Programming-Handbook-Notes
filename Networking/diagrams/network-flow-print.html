Network Flow — DNS → IP → TCP/TLS → HTTP → CDN / LB → Origin

Printable guide with the embedded diagram and detailed per-step flow states (IP addressing, TCP/IP, DNS, HTTPS, load balancing, firewalls, VPN/tunneling, proxies, CDN, SSH, PKI).

Overview (end-to-end)

This document explains the step-by-step states that a client request traverses when communicating with a public service on the Internet. It covers the resolution of a domain to IP, routing across the Internet, establishing reliable and secure connections using TCP and TLS, application-layer HTTP flow, and the network and security infrastructure that sits between the client and origin (CDN, load balancer, firewall, VPN, proxies, etc.).

  1. DNS resolution — client checks caches (browser, OS, recursive) then queries recursive resolver. Transport: UDP/53 (small queries), TCP/53 fallback, DoH (HTTPS) or DoT (TLS/853) for encrypted DNS.
    Key behavior: TTL-based caching, CNAME chaining, DNSSEC validation, glue records for delegation.
  2. Local network & NAT — Client has private IP (RFC1918). ARP/NDP resolves MAC addresses on the LAN. When leaving the LAN, source addresses are translated by NAT (PAT) to a public IP + ephemeral port.
    Key behavior: NAT mapping table, ephemeral port exhaustion risk, conntrack state for return traffic.
  3. Internet routing — IP packets traverse ISP networks and BGP-routed AS paths. Each router uses longest-prefix match for next hop. TTL is decremented; PMTU is considered to avoid fragmentation.
    Key behavior: BGP route selection, route propagation, anycast routing for CDNs.
  4. TCP connection establishment — Standard 3-way handshake (SYN / SYN-ACK / ACK). TCP state machine transitions from CLOSED → SYN-SENT → ESTABLISHED. Flow control (window), congestion control (slow-start, cwnd), and retransmission are handled by TCP.
  5. TLS handshake (if HTTPS) — ClientHello → ServerHello → Certificate, key exchange (ECDHE), derive symmetric keys, secure channel established. Certificate chain validated against trust anchors with OCSP/CRL checks or stapling.
  6. HTTP request/response — Application-layer request over TLS-encrypted stream. HTTP/1.1: persistent connections; HTTP/2: multiplexed streams; HTTP/3: QUIC over UDP with built-in security+transport.
  7. CDN / Edge handling — DNS or anycast routes client to nearest edge. Edge returns cached content on cache-hit; on cache-miss, edge fetches from origin, may terminate TLS, and apply WAF rules.
  8. Load balancer & reverse proxy — L4 (NLB) or L7 (ALB) chooses backend hosts using algorithms and health checks; may perform TLS termination and add headers (X-Forwarded-For or PROXY protocol).
  9. Firewall & security groups — Packet is inspected against ACLs or stateful SGs. Stateful devices track session state (conntrack) allowing return traffic. DPI/WAF may perform L7 inspection.
  10. Origin processing — Application server handles request, may communicate with private services (DB, cache) over internal network; responses go back through the same chain in reverse.

DNS — In-depth

Flow states

1 — Local caches: Browser and OS maintain caches. If a valid record exists (within TTL), no external query is needed.

2 — Stub resolver → Recursive: The client sends a query to configured resolver (ISP or public resolver). Transport typically UDP/53. Large responses or DNSSEC responses may use TCP/53.

3 — Iterative resolution: Recursive resolver queries root → TLD → authoritative NS. It may cache intermediary results and return final A/AAAA/CNAME records and TTLs.

Other considerations: Geo-DNS, anycast authoritative servers, DNS-based load balancing (multiple A records), DNSSEC with RRSIG validation, and encrypted DNS (DoH/DoT) to prevent on-path snooping.

IP Addressing & Routing (Network Layer)

Addresses: IPv4 (32-bit) and IPv6 (128-bit). Subnetting via CIDR determines network/prefix length.

On-LAN resolution: ARP (IPv4) / Neighbor Discovery Protocol (IPv6) map IP → MAC. Frames are transported via the data-link layer (Ethernet).

Next hop & routing: Packets destined outside the subnet are forwarded to default gateway. Routers use forwarding tables and perform longest-prefix match.

NAT: private address spaces are mapped to public IPs + ports (PAT). Careful with protocols that embed IPs in payloads (FTP) — require application-layer helpers.

TCP & TLS — Connection States

TCP handshake: SYN → SYN-ACK → ACK. After ESTABLISHED, reliable byte-stream semantics apply (seq/ack, congestion control, retransmits).

TCP teardown: FIN/ACK exchange; TIME_WAIT exists on the side that initiated close to allow late packets to be handled.

TLS (1.3 simplified): ClientHello (SNI, supported ciphers) → ServerHello + Certificate → Key exchange (ECDHE) → Encrypted application data. TLS provides confidentiality, integrity, and server authentication. Certificate validation chain must be anchored to a trusted root.

TLS termination choices: edge termination (LB or CDN), re‑encrypt to origin, or end‑to‑end TLS. Termination affects access to plaintext for WAFs and logging.

Load Balancer & Health Checks

L4 vs L7

L4: Operates at transport; forwards TCP connections using hashing methods. Often used for raw TCP or UDP services and for preserving client IP at the destination.

L7: Inspects HTTP headers and routes by host/path. Can perform advanced routing, TLS termination, content-based routing, header rewrites, and WAF integration.

Health checks: Periodic probes (TCP, HTTP) to backends decide whether to send traffic to a host. Ungraceful shutdowns require connection draining to avoid dropped requests.

CDN (Edge Caching)

CDNs use anycast and geo-routing to bring content near clients. Cache keys determine when a cached object is a hit (host+path+vary headers).

Cache-control headers, ETag/If-None-Match, and TTLs govern freshness. CDN edges may perform TLS termination and WAF filtering; on cache-miss they forward to origin.

Firewall & Security Groups

Firewalls reject or allow traffic based on rules. Stateful systems track connections and permit return traffic automatically. Network ACLs are stateless and must explicitly allow return traffic.

Proxies & CONNECT

Forward proxies handle outbound client traffic; reverse proxies sit before origin servers. For HTTPS via forward proxy, the CONNECT method establishes a TCP tunnel through the proxy and allows end-to-end TLS unless intercepted (TLS termination at proxy with certificate injection).

VPN & Tunneling

VPNs (IPsec, WireGuard, OpenVPN) create encrypted tunnels between endpoints. Packets are encapsulated and transported across public networks. Key exchange and authentication (certs/PSKs/keys) occur during tunnel setup. Be mindful of MTU and fragmentation when encapsulating packets.

SSH & Admin Access

SSH uses a TCP connection and its own key-exchange and authentication. Host keys are validated by clients via known_hosts. SSH supports remote port forwarding and SOCKS proxies, enabling secure tunnels for administrative tasks.

PKI & SSL Cert Lifecycle

Certificate issuance: generate private key + CSR → CA verifies domain ownership → CA issues certificate chain including intermediates → server presents chain at TLS handshake. Clients validate chain, check expiry, and optionally check revocation (OCSP/CRL). Use OCSP stapling to reduce client-side lookups. Renew and rotate before expiry.

Concrete End-to-End Example (HTTPS request)

  1. Browser requests https://app.example.com → checks DNS cache; no entry → queries recursive resolver (DoH or UDP/53).
  2. Resolver returns an anycast IP for a CDN edge. Browser opens TCP to that IP:443 (SYN).
  3. TLS handshake: ClientHello (SNI=app.example.com) → edge returns Certificate. Client validates chain and derives keys.
  4. Browser sends GET; CDN edge is a cache miss → forwards to origin ALB (may re-encrypt).
  5. ALB performs health check-based routing to a healthy backend, forwards traffic (may set X-Forwarded-For).
  6. Backend app receives request, queries DB in private subnet (mTLS optional). Response flows back through ALB → CDN → client.
